A JAX coordinate network parameterises the velocity model; a Devito finite-difference solver with a hand-written adjoint-state gradient evaluates the data misfit. jax.value_and_grad differentiates straight through both — across a process, or a container, boundary. Why split it in two

Not decoration — the two halves cannot share a dependency stack.

devito and the newer jax need different environments, and Devito's adjoint is not JAX-traceable — jax.grad cannot cross that boundary on its own. Tesseract makes the boundary explicit and typed, so each side keeps its own stack and its own way of computing a gradient.

Neither Tesseract knows the other exists: only a flat theta vector goes one way and a scalar loss comes back.

Architecture

Forward along the top, vector–Jacobian products back along the bottom.

siren_model/devito_fwi/
forward vp = vmin + (vmax−vmin)·σ(SIREN([x,z])) acoustic FD solve, L2 misfit over all shots
gradient JAX autodiff (jax_recipes) discrete adjoint-state (devitofwi)
stack jax, equinox devito, pylops, a C compiler

workflow.py runs jax.value_and_grad plus Adam over theta. JAX never traces the wave solve — it calls the Devito Tesseract's vector_jacobian_product endpoint, which is AcousticWave2D._loss_grad used verbatim.

The SIREN is a reparameterisation, not a regulariser. It maps a coordinate (x, z) to the velocity there — 2 inputs, 1 output, four hidden layers of 256, so 198,401 weights — and the whole model is that network evaluated on all 601 × 221 grid points. The optimiser therefore steps the weights, never the cells directly, and the sigmoid bounds the output into [1.4, 5.8] km/s by construction, so nothing needs clipping.

Marmousi, from a random start — no starting model, no multiscale continuation.

The velocity bounds are stated as constants rather than read from the true model, so the SIREN Tesseract never loads the answer. They only have to contain the model — but never be tighter than it, or a saturating sigmoid could not reach the extremes.

The wave solve dominates completely, as it should: 93.7 % of wall clock is inside the physics Tesseract. The Tesseract boundary itself — serialising theta out and dL/dθ back, 6000 times each way — does not appear in the budget.

Caveats

The starting model is a calibrated random SIREN (gain 8.775, σ = 0.300 km/s), not a plain random draw. The run had largely plateaued when it stopped — over the final 500 epochs the misfit moved 7 % and the model error 0.58 % — and it stopped at its epoch budget, not at a convergence criterion.

The correctness checks — 16 of them, including the gradient check — were run on a cheaper decimated grid, not at this size.

Verifying the composed gradient

The check that both VJPs are correct and consistent with each other.

workflow.py --check-grad perturbs theta along the gradient direction, re-runs the whole pipeline either side, and compares that slope against the composed adjoint. It passes only if both VJPs are right and agree with each other — a bug in either half breaks it. The tolerance is 3 %: 

-grad: adjoint +3.081590e-05  finite-diff +3.115019e-05  rel.err 1.07e-02  OK

test_pipeline.py checks the two halves separately as well — the JAX VJP to 1 %, and the Devito adjoint against single-cell finite differences to 5e-3.

These numbers come from the decimated development grid, not from the 601 × 221 run — at full size each check costs a wave solve. They test the code, which does not change with the grid, but they have not been re-run here.

A factor-of-two fix

PostProcessVP carries one change relative to Devito-fwi upstream: −grad/vp³ → −2·grad/vp³. Devito returns dL/dm for the squared slowness m = 1/vp², so the chain rule to velocity carries a factor of 2. With the upstream expression the adjoint is off by exactly 2×.

Running as containers

In-process mode keeps the demo to one command; container mode delivers the isolation.

make build
tesseract serve siren-model
tesseract serve devito-fwi
$PY workflow.py --served http://127.0.0.1:PORT1 http://127.0.0.1:PORT2

workflow.py is unchanged between the two modes — only how the clients are constructed differs, which is the point of the abstraction.

Implementation notes

The things that were not obvious.

The pool is warmed once

devito_fwi forks one worker per shot on the first call and reuses them, so Devito's JIT compilation and the observed-data modelling are paid once per served Tesseract rather than once per gradient.

apply computes the gradient anyway

_loss_grad(computegrad=False) has an upstream bug — it crops an unbound grad — so the loss-only shortcut is unusable. The forward solve dominates, so the wasted adjoint is a modest cost rather than a doubling.

Two implicit devito dependencies

matplotlib and pytest are import-time dependencies of devito 4.8.23's bundled seismic examples. A clean image needs them named explicitly, or the forked workers die.
